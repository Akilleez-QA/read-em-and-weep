## Semantic findings

**Total plans and signs.** Stable sorting uses the auxiliary-first carrier/mask/original-tag key. Inversion parity is the single alternating sign. Original owners and sorted owners remain separate immutable tuples, with full seed/occurrence/carrier/mask/tag provenance retained. T/Rsharp accept empty and singleton tuples as metadata; this does not assert that an arbitrary tuple degree is an implemented solver degree. F requires three owners. Same-seed validation and explicit occurrence-alias reporting are correct; an alias suppresses the canonical F join without inventing a geometric zero.

**Two repetition rules.** Repeated common keys `(carrier,mask,tag)` produce zero plans for every cochain. Repeated physical keys `(carrier,mask)` produce an additional zero only for the particular pulled-back F. T and Rsharp with equal physical labels but different tags survive and retain their frame route. This matches the imported source/common distinction; it does not propagate F's zero theorem through a solver or lift.

**Row-End frame correction.** For an Rsharp value canonically based at the sorted first vertex, let G be the transition from the original first vertex to the canonical first vertex. Pulling an endomorphism back to the original row frame requires `G^-1 X_canonical G`. The plan records exactly this left inverse/right transition order and multiplies by the parity once. The transition request retains the ordered `(original_first,canonical_first)` edge even when reverse ordered. Sorting that edge again or using only scalar parity would be incorrect. F/T are separately marked as scalar values in their fixed common finite frame.

The route is identity when the first common key is unchanged; full owners are still recorded. Empty tuples have no base owner. Degenerate zero plans explicitly require no transport evaluation, even if their descriptive route contains a nontrivial ordered edge. No transition is evaluated by frame planning. ToyProvider now declares `scalar_fixture_only`, so scalar fixtures named Rsharp are not evidence of End-valued evaluation.

**Lazy96 completeness.** The formula `k -> (k//16,k%16)` bijects indices0..95 with the six carriers and sixteen masks, with inverse `16*c+m`. The proof establishes completeness without scanning the domain. The descriptor retains seed, immutable occurrence and original tag; legal-mask low bits and standard-tag high bits stay distinct. It retains structural zero-weight labels. Iteration and owner construction refuse; single boundary label metadata is not an admitted complete fiber iteration.

**Canonical join and gates.** Eligible F descriptions pass the original owner tuple to FD and crosscheck its sorting sign, without multiplying a second sign. Repeated/aliased F and every T/Rsharp description remain normalization-only. Actual coefficient, alternating-coefficient, factor-stream and owner methods unconditionally raise before normalization, frame routing, exponent validation or zero/support shortcuts, independent of a changed mode attribute. A mathematically zero plan therefore cannot leak an actual coefficient result through the gate.
