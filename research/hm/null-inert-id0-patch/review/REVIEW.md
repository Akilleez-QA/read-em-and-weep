4. **Exactly one certification division is retained and shared.** The new method extracts the componentwise denominator monomial, divides the whole numerator by the entire residual denominator once, rejects any nonzero remainder, and retains the quotient and shift. All three reads use that quotient. In Q[x1,x2,x3,x4], the residual has no variable factor, hence is coprime to every monomial; therefore A/B is Laurent exactly when the residual divides A. Single-divisor polynomial division gives the appropriate zero-remainder test, including residuals without a constant term. The coefficient translation is `target = exponent + shift`.
5. **Identity, lifetime and poison checks are present.** The context requires the exact production `Execution` class and immutable nonempty string-tuple frame labels. Weighted accumulation uses the same Execution's exact conversion, multiplication and addition methods. Exhausted Execution state propagates through these methods and pre/post checks. No extra independent meter is introduced. These are ordinary API guarantees, not protection against private-symbol access, reflection, direct attribute inspection, malicious subclasses, interpreter mutation or concurrent mutation. Already returned immutable values cannot be revoked.
6. **Weights and indexes are correct.** The retained JSON record's digest and ID0 payload match the manifest. Expanding `(x1*x2 + x3*x4)^2` gives weights 1, 2, 1 and monomials `(2,2,0,0)`, `(1,1,1,1)`, `(0,0,2,2)`.
