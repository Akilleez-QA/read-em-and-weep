# Independent preparation resource review

Reviewed 2026-10-16 at immutable PR90 head 779c1f7604db6fd48ce6e389b30a96f7aebef9f7.

The current physical CLI, private child flag and private physical body all refuse before source reads or arithmetic. The generic mathematical kernel is not a hostile-code sandbox, and the plan accurately states ordinary module integrity as a premise. Current source-byte authentication binds the fixed spec, source manifest and each of five source files; it does not yet authenticate the executable modules at launch.

The rational meter charges constructions and integer primitives, including normalization divisions, and rejects oversized intermediate multiplication/addition before allocation. These counters are explicitly software counters rather than native bit-work or historical polynomial-product units. Poisoned contexts reject further arithmetic. Conservative height refusal is permitted. Parsing and Python container/interpreter overhead are covered only by the process limits, not these arithmetic counters.

The artificial supervisor sets matching parent and child address-space and CPU hard limits. The documented combined maximum is two processes, 512 MiB virtual address space and 30 CPU seconds; this is not measured resident memory or a claim about historical shared accounting. Its child timeout is 20 wall seconds. The no-descendants/network guards are cooperative and adequate only for the inspected module under normal integrity.

The current 64 KiB output check is performed after capture_output collects the child output. It is an acceptance/retention bound, not a streaming transport bound. The address-space cap remains the outer memory protection. A release should either implement bounded streaming capture or explicitly state and accept the distinction. The child emitter itself checks serialized length before writing; the appended newline needs to be included in the byte contract. RLIMIT_FSIZE does not impose a pipe-output bound.

Preparation is acceptable as a dormant artifact. No physical execution release follows. Before any later release, review a separate patch that:

1. Authenticates executable module bytes in addition to the existing source and selection pins.
2. Runs the one fixed physical body only through the separately reviewed supervised child path, with the same fixed point/triple and no adaptive retry.
3. Preserves truthful failure provenance: distinguish evaluation never started from partial evaluation that refused, failed, or was killed. The current artificial-only exception output cannot simply be reused with physical_source_evaluated=false after physical arithmetic begins.
4. Handles all child failure/exception/timeout paths as inconclusive, with no partial value promoted to mathematical evidence, and records actual process outcome and retained byte counts.
5. States whether the 64 KiB limit is an emitted/retained-record limit or an enforced capture limit, including the newline and stderr.

These are release requirements, not findings that the dormant preparation has executed or violated its hold. Completion under the proposed limits is unproved. The separate historical replay and its accounting remain unchanged.
