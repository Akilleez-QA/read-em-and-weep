# Parallel proof-repair campaign

Status: planning and readiness gates. A research plan is not a theorem, an executed experiment, or a completed repair.

## Objective

Produce checked mathematical reductions or reproducible universal constructions that settle remaining parts of the fixed-source proof repair. Separate three questions throughout:

1. Which necessary quotient profiles can be excluded?
2. Which feasible abstract configurations are incompatible with the **fixed original HM multiplication tensors**?
3. Can the actual source and higher-lifting equations be completed, with the exact second-symbol quotient retained?

The primary objective is a complete checked argument. A negative result that closes an entire precisely defined method or ansatz is also a useful deliverable. PR counts, reviews, elapsed compute, and repeated status reports are not substitutes for either.

## Gates before expensive work

### Gate 0: reconcile the current state

1. Refresh PR1 and the heads of every dependency used by a task.
2. Confirm the project remains active, the task is unclaimed or explicitly handed off, and the proposed result is not already proved.
3. Replay the frontier validator. Keep new exclusions separate from older source-edge cuts.
4. Read complete logs: an empty log, a partial list of checks, or absence of a final certificate is **not PASS**.
5. Identify the exact experiment run and checkpoint location. Preserve previous run artifacts read-only.

### Gate 1: mathematical readiness

Each task must state its domain, quantifiers, source dependence, and complete input/output types. Explicitly identify:

- actual fixed source versus abstract family;
- coefficient directions versus operators versus source-restricted actions;
- balanced coordinates versus physical coordinates;
- ordinary sections versus ideal-valued cohomology;
- scalar nonvanishing versus the fourth boundary;
- generic statements versus every-parameter statements;
- genuine constant quotient connections versus arbitrary bundle complements.

A task failing a typing or hypothesis check is corrected before compute begins.

### Gate 2: smoke certificate

Use free symbols and small canonical fixtures to test the exact maps, signs, basis transport and reconstruction identities. Require both a positive fixture and a deliberately broken fixture. Do not specialize actual coefficients or selected source points to make a difficult identity appear easier.

### Gate 3: bounded burn

For a newly started wave, the proposed initial envelope is:

- 90 minutes of wave wall time before an explicit checkpoint review;
- no more than two simultaneous CPU-heavy local jobs;
- initially no more than 20 CPU-minutes and 1.5 GiB address space per local job;
- no new paid capacity, external API spending, credential creation, or persistent infrastructure;
- no automatic escalation of a failed limit.

These limits are conservative scheduling defaults, not evidence that an already-started external run uses them. Inspect the actual run configuration and reconcile it before intervention. Native research concurrency and local CPU concurrency are different resources.

Checkpoint each completed block independently. Store input hashes, command, code version, elapsed time, termination reason and output hashes. A timeout is inconclusive, not a mathematical negative result. Resume only from a verified checkpoint and never silently relaunch an old consumed experiment under a new label.

### Gate 4: acceptance

Accept a result only when:

1. its exact claim is written with dependencies and limitations;
2. every claimed computation has a complete output certificate;
3. an independent verifier checks the new substantive step;
4. the author resolves all reported counterexamples or gaps;
5. the immutable publication is read back and matches the checked files.

Reviews support verification but do not count as a new research result by themselves.

## Live pivot rules

| Observation | Action |
|---|---|
| A family is already excluded | Retire its search task; preserve its negative certificate and identify a genuinely larger or different family |
| A theorem forces a unique remaining type | Replace enumeration with the exact forced type; notify dependent tasks |
| An abstract construction realizes all current tests | Stop trying to exclude it with those same tests; move to fixed-source compatibility |
| A basis or quotient was incomplete | Quarantine dependent conclusions, repair completeness, rerun only affected checks |
| A coordinate or adjoint convention disagrees | Stop promotion immediately; produce a transport regression before continuing |
| A residual is nonzero | Determine whether it is a genuine quotient obstruction or a missing gauge/source channel before interpreting it |
| A result changes a prerequisite | Mark downstream tasks stale and revalidate them before reuse |
| A job exceeds its cap | Preserve checkpoint, report exact bottleneck, and choose an algebraic simplification or smaller block decomposition |
| A complete new proof is proposed | Check the whole dependency chain, not only the last lemma; no upstream solution claim before that succeeds |

## Deliverable contract

Every production work package should return:

- one bounded theorem, construction, counterexample, or precise new obstruction;
- a short proof with immutable dependencies;
- reproducible code and deterministic certificates where computation is involved;
- a list of unrun checks and known limitations;
- the next owner and the exact remaining question.

Publish small focused draft PRs. Stack only genuine dependencies. Do not merge unrelated results into a large research PR merely because the campaign itself is large. Keep the living paper modular and update its status only from accepted results.

## Explicit non-goals and guardrails

No selected actual HM coefficient, point, matrix, instance-rank evaluation, or actual-parameter scan is introduced by this plan. Universal symbolic construction, representation arithmetic, abstract feasibility and deductive source-specific arguments remain distinct from such evaluation. Changing that boundary requires a separately explicit scope decision.

Do not restart an ended local-model experiment or repeat a consumed one-shot experiment as routine recovery. Any new burn has its own question, manifest, limits and outputs. No upstream posting, complete-repair announcement, or algebraicity inference follows from a component result.

## Reproduction

Run from this directory:

    python verify_frontier.py
    python -m unittest -v test_frontier.py

The verifier checks a pinned accounting artifact, not the mathematical truth of every imported proof. Written audits are not proof-assistant certification. The work-package modules and campaign gates specify what additional evidence is needed before a result can be promoted.
